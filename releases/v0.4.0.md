# v0.4.0

Adds an optional short-query guard and prepares the shared minor version 0.4.0
under the project's 0.x feature policy. The guard is **off by default**.

- Enable with `cs --short-query-guard`, or export
  `COMMAND_SEARCH_SHORT_QUERY_GUARD=1` for standalone search and the shell hotkey.
  `--no-short-query-guard` overrides the environment for one launch.
- Automatic interactive edits hold a trailing unfinished keyword shorter than
  three searchable characters, including after backspacing. Completed keywords
  remain searchable, with a visible hint identifying the held suffix.
- Space, Enter, or result navigation explicitly submits all current keywords.
  Explicit initial queries and `--matches` continue to support short terms.
- Existing matching, ranking, effect filters, frozen references, argument
  guidance, and unexecuted shell handoff remain available. Both platform catalogs
  include the new positive/negative guard flags and their descriptions.

Since the latest existing local tag, v0.2.0, this release also includes:

- `command-search` / `cs`, live purpose-keyword search across the full macOS and
  Ubuntu catalogs, with frozen references above command-complete drafting.
- Hybrid updates: a 250 ms idle delay, immediate Space submission, background
  queries, superseded-result rejection, and responsive keyboard input.
- Bash vi-mode Ctrl+X/Ctrl+G prefix handling that tolerates a pause between keys
  and repeated sourcing without changing the global Readline timeout.
- Expanded source-backed command and option descriptions, offline SQLite search
  snapshots, coverage reporting, and shared installation/versioning with cc.

Runtime remains Python 3.10+ with standard-library curses/SQLite only. The utility
does not execute the draft. Ctrl+G opens cc; Ctrl+X then Ctrl+G opens cs.

for explicit metadata gaps. These notes prepare a release; no tag or GitHub
